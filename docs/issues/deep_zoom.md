# Deep zoom

## Статус

Отложенная функция. Текущий WebGL2-рендерер использует `highp float` и рассчитан
на обычную интерактивную навигацию, а не на экстремальное увеличение.

## Проблема

Координаты камеры вычисляются в JavaScript с двойной точностью, но при передаче в
fragment shader преобразуются в 32-битные числа. Когда размер видимой области
становится сопоставим с шагом представимого `float` около координат центра,
соседние пиксели получают одинаковые координаты. Это проявляется как:

- блоки и полосы вместо деталей;
- дрожание изображения при перемещении камеры;
- остановка зума, хотя значение масштаба продолжает изменяться.

Переход с WebGL2 на WebGPU сам по себе проблему не решает: базовая и наиболее
переносимая арифметика шейдеров там также использует `f32`.

## Предлагаемая реализация

Основной вариант — perturbation rendering:

1. На CPU вычислять одну опорную орбиту около центра кадра с произвольной
   точностью.
2. Передавать опорную орбиту на GPU через texture или storage buffer.
3. Для каждого пикселя вычислять только малое отклонение от опорной орбиты.
4. Обнаруживать пиксели с потерей устойчивости и пересчитывать их относительно
   дополнительной опорной точки.
5. Сохранять текущий быстрый shader path для масштаба, где точности `float`
   достаточно.

Для первой версии допустимо реализовать double-double арифметику в GLSL. Она
проще perturbation rendering, но существенно увеличивает число операций на
пиксель и даёт меньшую глубину.

## Изменения архитектуры

- Представить центр камеры парой `high`/`low`, а масштаб — сериализуемым
  значением без раннего преобразования к `number`.
- Добавить backend `DeepZoomRenderer`, сохранив текущий `FractalRenderer` как
  быстрый backend.
- Расширить описание формулы метаданными, необходимыми для вычисления опорной
  орбиты на CPU.
- Добавить worker для arbitrary-precision вычислений, чтобы не блокировать UI.
- Добавить индикатор подготовки опорной орбиты и отмену устаревших вычислений
  при движении камеры.

## Критерии готовности

- Детали остаются стабильными как минимум до увеличения `1e30` для множества
  Мандельброта.
- Перемещение и зум не блокируют основной поток.
- При смене кадра устаревший расчёт опорной орбиты отменяется.
- Обычный режим не получает заметной регрессии производительности.
- Архитектура сохраняет возможность добавлять новые формулы без изменений UI и
  базового WebGL2-рендерера.
