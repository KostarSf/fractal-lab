# Deep zoom

## Статус

Реализовано для всех текущих escape-time формул.

Начиная с увеличения `10 000×` просмотрщик автоматически переключается с
обычного escape-time shader на perturbation renderer. Порог сравнивается с
увеличением из интерфейса, а не с абсолютным значением масштаба. Формулы без
зарегистрированного deep-zoom backend продолжают использовать быстрый WebGL2
renderer.

## Алгоритм

Worker выбирает внутри видимой области точку `c` с наиболее длинной орбитой и
вычисляет её с динамической десятичной точностью:

\[
Z_0 = 0,\qquad Z_{n+1} = Z_n^2 + c
\]

Для соседнего пикселя GPU хранит только отклонение `Δ`:

\[
\Delta_{n+1}
=

2 Z_n \Delta_n + \Delta_n^2 + \delta c
\]

Опорная орбита передаётся в `RGBA32F` texture. Каждый её компонент представлен
парой `high`/`low`, чтобы сохранить больше точности, чем один GPU `float`.

Если сумма опорной орбиты и отклонения становится меньше самого отклонения,
shader выполняет rebasing и продолжает расчёт с начала опорной орбиты. Это
уменьшает характерные perturbation glitches около точек сильного сокращения.
Исчерпание короткой опорной орбиты также запускает rebasing, но не ограничивает
общее число итераций пикселя. Благодаря этому детализация не зависит от того,
находится ли структура в центре или у края кадра.

## Архитектура

- `src/math/high-precision.ts` — каноническая сериализуемая камера и десятичные
  преобразования без раннего перехода к `number`.
- `src/deep-zoom/reference-orbit.worker.ts` — изолированный расчёт опорной
  орбиты с `decimal.js`.
- `src/deep-zoom/reference-orbit-client.ts` — создание worker и отмена
  устаревших запросов.
- `src/renderer/deep-zoom-renderer.ts` — загрузка orbit texture и WebGL2
  perturbation rendering.
- `src/renderer/deep-zoom-shader.ts` — perturbation recurrence, rebasing,
  escape test и общая схема окрашивания.

Описание формулы содержит необязательные метаданные `deepZoom`. Поэтому новые
обычные формулы не требуют изменений UI или рендереров, а дополнительный
deep-zoom backend можно подключить явно.

## Поведение интерфейса

- При подготовке новой опорной орбиты отображается индикатор.
- Во время движения предыдущая орбита остаётся доступной для preview.
- Новое изменение камеры отменяет незавершённый worker и ставит в очередь
  актуальный расчёт.
- При каждом расчёте worker проверяет сетку точек внутри viewport и выбирает
  наиболее устойчивую опорную орбиту.
- После завершения индикатор показывает количество десятичных разрядов.
- Если deep backend недоступен, обычный renderer остаётся рабочим.

## Ограничения

Максимальное увеличение текущих perturbation backend'ов временно ограничено
значением `1.00e+35×`. Для Мандельброта это соответствует масштабу `3.1e-35`.
Опорная орбита вычисляется с произвольной точностью, однако пиксельное отклонение
в текущем WebGL2 shader остаётся `highp float`. При дальнейшем увеличении
изображение начинает заливаться однородным цветом. Камера останавливается на
пределе независимо от способа масштабирования. Для более глубоких масштабов
потребуется extended-range представление мантиссы и экспоненты либо WebGPU
backend с аналогичной программной арифметикой.

Perturbation metadata и отдельные backend'ы добавлены всем текущим escape-time
формулам. Архитектура и формулозависимые рекуррентности описаны в
[отдельном issue](./deep_zoom_remaining_formulas.md).

## Проверка критериев

- [x] Детали стабильны при увеличении больше `1e30`.
- [x] Расчёт опорной орбиты не блокирует основной поток.
- [x] Устаревший расчёт отменяется при изменении камеры.
- [x] Обычный режим не выполняет arbitrary-precision вычисления.
- [x] Новые обычные формулы не требуют изменений UI и базового renderer.
