# Deep zoom для остальных формул

## Статус

Запланировано.

Сейчас perturbation backend реализован только для множества Мандельброта.
Необходимо добавить deep zoom для оставшихся формул:

- Julia;
- Tricorn;
- Burning Ship;
- Phoenix.

Переключение должно происходить по общему правилу, начиная с увеличения
`10 000×`.

## Цель

Переиспользовать существующую инфраструктуру точной камеры, worker, отмены
устаревших запросов, выбора опорной точки, orbit texture и UI-индикатора, но
вынести формулозависимые вычисления в отдельные deep-zoom backend'ы.

Обычный WebGL2 renderer и подключение новых формул без deep zoom не должны
усложниться.

## Архитектурные изменения

- Заменить единственный тип `mandelbrot-perturbation` на реестр deep-zoom
  backend'ов.
- Передавать в worker идентификатор backend'а и необходимые параметры формулы.
- Разделить общую логику расчёта reference orbit и формулозависимый шаг
  итерации.
- Поддержать разные начальные условия для отклонения `Δ`.
- Позволить backend'у определять формат состояния орбиты. Для Phoenix
  потребуется хранить текущее и предыдущее значения.
- Разделить общий код окрашивания и формулозависимые perturbation-фрагменты
  shader'а.
- Сохранить transferable-передачу буферов из worker без копирования.
- Пересчитывать reference orbit при изменении параметров активной формулы.
- Не включать deep zoom для формулы, пока её backend не зарегистрирован.

## Формулы

### Julia

Текущий просмотрщик отображает динамическую плоскость с фиксированной
константой `c`:

\[
Z_0 = p,\qquad Z_{n+1} = Z_n^2 + c
\]

Для опорной точки `P` и отклонения пикселя `\delta p`:

\[
\Delta_0 = \delta p
\]

\[
\Delta_{n+1} = 2Z_n\Delta_n + \Delta_n^2
\]

Значение параметра `c` должно передаваться как в worker, так и в deep-zoom
shader.

### Tricorn

\[
Z_0 = 0,\qquad Z_{n+1} = \overline{Z_n}^{\,2} + c
\]

\[
\Delta_{n+1}
=2\overline{Z_n}\,\overline{\Delta_n}
{}+\overline{\Delta_n}^{\,2}
{}+\delta c
\]

Reference orbit и GPU-рекуррентность должны одинаково применять комплексное
сопряжение.

### Burning Ship

Обозначим:

\[
A(z) = |\operatorname{Re}(z)| + i|\operatorname{Im}(z)|
\]

Тогда:

\[
Z_{n+1} = A(Z_n)^2 + c
\]

Для perturbation необходимо вычислять:

\[
\delta A_n = A(Z_n + \Delta_n) - A(Z_n)
\]

\[
\Delta_{n+1}
=2A(Z_n)\delta A_n
{}+\delta A_n^2
{}+\delta c
\]

Из-за смены знаков около действительной и мнимой осей это кусочно-гладкая
формула. Необходимо отдельно обнаруживать sign-boundary glitches и выполнять
rebasing либо fallback для нестабильных пикселей.

### Phoenix

Для текущей реализации:

\[
Z_{n+1} = Z_n^2 + c + pZ_{n-1}
\]

Нужно хранить отклонения для двух последовательных состояний:

\[
\Delta_{n+1}
=2Z_n\Delta_n
{}+\Delta_n^2
{}+p\Delta_{n-1}
\]

Начальные условия для динамической плоскости:

\[
\Delta_0 = \delta p_{\text{pixel}},\qquad \Delta_{-1}=0
\]

Параметры `c` и `p` должны участвовать в worker-запросе, ключе актуальности
reference orbit и shader uniforms.

## Порядок внедрения

1. Выделить реестр backend'ов и общий протокол worker.
2. Реализовать Julia как ближайший к существующему Mandelbrot backend.
3. Добавить Tricorn с сопряжённой perturbation-рекуррентностью.
4. Расширить формат состояния орбиты и реализовать Phoenix.
5. Реализовать Burning Ship вместе с обработкой sign-boundary glitches.
6. Добавить визуальные regression-пресеты для каждой формулы.

## Критерии готовности

- [ ] Все четыре формулы автоматически переходят в deep zoom при увеличении
      `10 000×`.
- [ ] При переходе через порог `10 000×` изображение не скачет и не меняет
      положение структуры.
- [ ] Панорамирование не вызывает слипания координат или зависимости
      детализации от положения структуры на экране.
- [ ] Изменение параметров Julia и Phoenix отменяет устаревший worker-запрос и
      рассчитывает новую опорную орбиту.
- [ ] Расчёт arbitrary-precision reference orbit не выполняется в основном
      UI-потоке.
- [ ] Включение и отключение сглаживания цветов работает одинаково в обычном и
      deep-zoom режимах.
- [ ] Для каждой формулы есть unit-тест reference orbit и perturbation step.
- [ ] Для каждой формулы есть браузерный regression-сценарий до и после
      панорамирования.
- [ ] Существующий Mandelbrot backend и формулы без deep-zoom metadata не имеют
      регрессий.

## Вне текущей задачи

- Deep zoom глубже ограничения текущего `highp float` backend.
- Переход с WebGL2 на WebGPU.
- Распределённый или серверный рендеринг.
