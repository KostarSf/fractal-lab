# Mandelbulb, Buddhabrot и Fractal Flame

## Статус

Исследование и общий backlog. Перед реализацией каждый фрактал следует вынести
в отдельный issue с выбранным алгоритмом, UX и бюджетом производительности.

Поддержка deep zoom в первую версию не входит.

## Цель

Подготовить архитектуру просмотрщика к трём принципиально разным способам
рендеринга:

- Mandelbulb — трёхмерный ray marching;
- Buddhabrot — стохастическое накопление орбит;
- Fractal Flame — вероятностная iterated function system с histogram
  accumulation.

Эти режимы не следует встраивать в существующий escape-time fragment shader
как дополнительные формулы.

## Общая архитектура

- Ввести реестр renderer backend'ов с единым lifecycle.
- Разрешить backend'у определять собственный тип камеры и схему управления.
- Разрешить progressive renderer'у публиковать прогресс и продолжать
  накопление между кадрами.
- Отменять worker/GPU-задачи при изменении параметров или backend'а.
- Хранить presets отдельно для каждого типа renderer'а.
- Показывать только применимые настройки, показатели прогресса и действия
  экспорта.
- Определить общий контракт для resize, временного preview и финального
  качества.
- Добавить capability checks и понятный fallback при отсутствии необходимых
  WebGL2 extensions.

## Mandelbulb

Потребуется отдельная 3D-камера и distance-estimator shader:

- orbit iteration для оценки расстояния;
- ray marching с ограничением числа шагов;
- вычисление нормали;
- освещение, фон и ambient occlusion;
- управление orbit-camera мышью или touch-жестами;
- снижение количества ray-march steps во время движения;
- защита от зависания GPU на слабых устройствах.

Перед реализацией определить:

- степень Mandelbulb и доступные пользователю параметры;
- начальные presets;
- модель освещения;
- ограничения разрешения и числа шагов;
- нужен ли экспорт изображения с повышенным качеством.

## Buddhabrot

Потребуется progressive Monte Carlo pipeline:

- генерация комплексных sample-точек;
- предварительная проверка, что орбита покидает множество;
- повторный проход с накоплением всех точек убежавшей орбиты;
- accumulation buffer с достаточным динамическим диапазоном;
- периодический tone mapping без остановки UI;
- независимые диапазоны итераций для RGB-каналов как опциональный режим;
- детерминированный seed для воспроизводимых regression-тестов.

Перед реализацией сравнить варианты:

- CPU workers с transferable-буферами;
- WebGL2 transform feedback и additive blending;
- WebGPU compute как отдельный будущий backend.

## Fractal Flame

Потребуется отдельная модель данных для стохастической IFS:

- набор affine transforms с весами;
- библиотека nonlinear variations;
- симметрия и финальное преобразование;
- накопление цветовой статистики и плотности;
- logarithmic density estimation, gamma и tone mapping;
- сериализация и импорт presets;
- редактор transforms и variations.

Первый отдельный issue должен определить минимальный набор variations и решить,
входит ли визуальный редактор в MVP. Без этого Fractal Flame рискует стать
несовместимым набором жёстко заданных presets.

Детерминированные IFS с треугольниками и прямоугольниками рассматриваются в
[отдельном issue](./geometric_ifs_fractals.md).

## Предлагаемый порядок

1. Завершить общий renderer registry на более простых Newton, Nova и Clifford.
2. Сделать технический prototype Mandelbulb с фиксированными параметрами.
3. Проверить accumulation pipeline на Buddhabrot.
4. На основе результатов выбрать WebGL2 либо WebGPU для длительных
   накопительных задач.
5. Спроектировать формат данных и редактор Fractal Flame.

## Критерии декомпозиции

- [ ] Для каждого фрактала создан отдельный implementation issue.
- [ ] Выбран renderer backend и документирован fallback.
- [ ] Определены камера, управление и набор параметров MVP.
- [ ] Зафиксирован бюджет времени интерактивного и финального кадра.
- [ ] Определены правила отмены и сброса progressive calculation.
- [ ] Подготовлены воспроизводимые presets для тестирования.
- [ ] Описаны unit-, browser- и visual-regression тесты.
- [ ] Решено, какие вычисления выполняются в worker, WebGL2 или WebGPU.

## Вне текущей задачи

- Непосредственная реализация трёх renderer'ов.
- Deep zoom.
- Серверный или распределённый рендеринг.
