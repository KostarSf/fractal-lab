# Newton, Nova и Clifford attractor

## Статус

Реализовано.

## Реализация

- Реестр формул разделён на `escape-time`, `root-basin` и `point-attractor`.
- Newton и Nova используют отдельный fullscreen basin shader с комплексным
  делением, проверкой сходимости и защитой от нулевой производной.
- Newton классифицирует три корня `z³−1`, Nova различает сходящиеся, убегающие
  и неразрешённые точки.
- Clifford рассчитывает траекторию в отменяемом worker и передаёт
  `Float32Array` через transferable buffer.
- GPU отображает Clifford через `GL_POINTS` и additive blending; экспозиция и
  размер точки изменяются без повторного расчёта траектории.
- UI адаптирует итерации, параметры, сглаживание и подпись renderer'а к
  выбранному типу формулы.
- Все renderer'ы имеют явный `dispose`, а переключение режимов сбрасывает
  несовместимое WebGL state.

## Цель

Добавить три фрактала из других областей динамических систем без поддержки
deep zoom:

- Newton — бассейны притяжения корней;
- Nova — параметрическая модификация метода Ньютона;
- Clifford attractor — хаотический аттрактор с накопительным отображением
  траектории.

Newton и Nova вычисляются независимо для каждого пикселя. Clifford строится
последовательным накоплением точек, поэтому ему нужен отдельный renderer.

## Архитектурные изменения

Текущий `FractalFormula` описывает только escape-time формулы. Его необходимо
заменить либо дополнить discriminated-конфигурацией renderer'а:

- `escape-time` — существующие формулы;
- `root-basin` — Newton и Nova;
- `point-attractor` — Clifford.

Общими должны остаться:

- выбор формулы и начальная камера;
- схема параметров и Pinia state;
- resize и временное снижение качества во время взаимодействия;
- палитры и обработка ошибок WebGL;
- единый lifecycle `setFormula`, `resize`, `render`, `dispose`.

Нерелевантные конкретному renderer'у элементы управления следует скрывать, а
не придавать им искусственное значение.

## Newton

Для первой версии использовать полином:

\[
f(z)=z^3-1,\qquad f'(z)=3z^2
\]

Итерация:

\[
z_{n+1}=z_n-\frac{f(z_n)}{f'(z_n)}
\]

Каждый пиксель задаёт начальное значение `z₀`. Расчёт заканчивается, когда
точка приблизилась к одному из трёх корней, либо достигнут лимит итераций.

Окрашивание:

- оттенок определяется номером ближайшего корня;
- яркость или насыщенность определяется скоростью сходимости;
- точки без сходимости получают отдельный нейтральный цвет;
- деление около `f'(z)=0` не должно порождать `NaN` или артефакты всего кадра.

Параметры первой версии:

- допуск сходимости;
- максимальное число итераций;
- опционально — relaxation factor после стабилизации базовой версии.

## Nova

Для первой версии зафиксировать Mandelbrot-подобную параметрическую плоскость:

\[
z_0=1
\]

\[
z_{n+1}
=

z_n-r\frac{z_n^3-1}{3z_n^2}+c
\]

Координата пикселя задаёт `c`, а `r` является настраиваемым relaxation factor.

Перед реализацией необходимо зафиксировать условия завершения и окрашивания:

- сходимость по малому значению `|zₙ₊₁-zₙ|`;
- выход за escape radius;
- достижение лимита итераций;
- различимые цвета для сходящихся, убегающих и неразрешённых точек.

Параметры:

- `r`, по умолчанию `1`;
- escape radius;
- допуск сходимости;
- максимальное число итераций.

Архитектура комплексного деления, проверки сходимости и защит от `NaN` должна
переиспользоваться с Newton.

## Clifford attractor

Итерация:

\[
x_{n+1}=\sin(ay_n)+c\cos(ax_n)
\]

\[
y_{n+1}=\sin(bx_n)+d\cos(by_n)
\]

Параметры:

- `a`, `b`, `c`, `d`;
- число пропускаемых начальных итераций;
- число отображаемых точек;
- экспозиция или плотность;
- размер точки.

Начальный preset:

```text
a = -1.4
b =  1.6
c =  1.0
d =  0.7
```

### Renderer

- Вычислять траекторию вне основного UI-потока либо непосредственно на GPU.
- Пропускать начальный участок траектории до стабилизации.
- Передавать точки transferable-буфером и рисовать их с additive blending.
- Для качественной плотности предусмотреть offscreen accumulation texture и
  отдельный tone-mapping pass.
- При изменении параметров или выборе другой формулы отменять устаревший
  расчёт и очищать накопление.
- Во время движения камеры допускается уменьшать количество точек, после
  завершения взаимодействия выполнять полный проход.
- При отсутствии необходимых WebGL extensions использовать документированный
  fallback с RGBA8 accumulation.

## Порядок внедрения

1. Ввести тип renderer'а и фабрику renderer lifecycle.
2. Выделить общие GLSL-функции комплексной арифметики.
3. Реализовать Newton и окрашивание бассейнов.
4. На базе Newton реализовать Nova и её параметры.
5. Добавить worker или GPU pipeline для траектории Clifford.
6. Реализовать accumulation и tone mapping для Clifford.
7. Добавить presets и визуальные regression-тесты.

## Критерии готовности

- [x] Newton корректно различает три бассейна корней `z³−1`.
- [x] Nova отображает параметрическую плоскость и реагирует на изменение `r`.
- [x] Защита комплексного деления не допускает `NaN`, мерцания или ошибок
      WebGL.
- [x] Clifford отображает плотность траектории, а не соединённую ломаную.
- [x] Расчёт Clifford не блокирует основной UI-поток.
- [x] Устаревший расчёт Clifford отменяется при изменении параметров и
      переключении формулы.
- [x] Камера, resize и управление мышью работают во всех трёх режимах.
- [x] UI показывает только релевантные выбранному renderer'у настройки.
- [x] Для Newton и Nova есть unit-тесты итерации и классификации результата.
- [x] Для Clifford есть unit-тест траектории и браузерный regression-тест
      накопительного renderer'а.
- [x] Существующие escape-time и deep-zoom backend'ы не имеют регрессий.
